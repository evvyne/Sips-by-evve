# ❄️ Sips by Evve

A single-page web app for managing a TikTok Live snowglobe tumbler business: inventory/stock, costs, orders, and profit. No build step, no backend — just one HTML file.

## Features

- **Dashboard** — revenue, costs, profit/margin, inventory value, low-stock alerts, orders awaiting payment, recent orders.
- **Inventory** — add/edit/delete products, each assigned a **Type**: `Tumbler`, `Stickers`, or `Others` (kitchen towel, syringe, any other supply). Stickers get an extra **Theme** dropdown (e.g. "A - Stitch", "B - Winnie the Pooh" — pick an existing one or "+ Add new theme…") to group codes, and each Theme's stickers are collapsed into a click-to-expand group so the list doesn't get long. Every product can have a **photo** — click any thumbnail (in the table or the upload preview) to open it enlarged; close with the × button, Escape, or clicking outside the image. Also tracks cost & selling price, stock levels, low-stock threshold, and where you bought it (see below).
- **Purchase source** — each product has two optional fields: **Bought from (platform)** (e.g. WeChat, Taobao, Shopee — with autocomplete suggestions) and **Seller / contact / link** (a username, or a full link — if it looks like a URL it becomes clickable). This lives directly on the product in Inventory rather than a separate tab, since sourcing info is really a property of the item itself, and keeping it there means it's visible right where you're already looking when restocking.
- **Costs drive restocking** — when you log a cost in the Costs tab, pick the **Related product** and fill in the **Quantity purchased** field that appears. Saving that cost entry automatically adds the quantity to that product's stock and updates its cost price (Amount ÷ Quantity) — no separate Inventory step, and no duplicate "700ml tumbler" row just because the price went up. Don't have the product in Inventory yet? Pick **+ Add new product…** instead of an existing one — a small "New product details" section appears (name, type, theme for stickers, variant, SKU, selling price, low-stock threshold) and it's created automatically with the stock/cost from this entry, so you never have to jump to Inventory first just to log a purchase. This only applies when you first create the entry; editing an existing cost later won't move stock again or create a second product, so you can safely fix a typo in the amount afterwards.
- **Adjust stock** — use the **Adjust** button on any product in Inventory for quantity *corrections* that aren't a purchase: e.g. a recount, or logging unaccounted loss (glycerin/glitter used up, spillage, damage). If you lower the quantity, pick a reason and it can log the lost value as a **wastage/loss** Cost entry at the current cost price. If you're increasing stock because you bought more, do that from the Costs tab instead (see above) so it's linked automatically — the panel reminds you of this.
- **Costs** — log costs by category (materials, packaging, shipping, ads, TikTok fees, other), optionally tied to a product (and quantity, for restocks — see above). Use this for anything money left your pocket for, including things you can't track per unit like a batch of glitter. The list is sorted newest first (by date, then by when each entry was actually created), so anything you just logged — including wastage entries created from Inventory's Adjust stock — always shows at the top.
- **Multi-currency purchases** — both the Inventory cost-price field and Costs amount field have a "Paid in a different currency? Convert to RM" helper: enter the foreign amount (e.g. CNY) and the exchange rate you got that day, and it converts to RM for you. For Costs entries, the original foreign amount/currency/rate is kept and shown as a small note under the amount, so you still have a record of what you actually paid even though everything totals up in RM.
- **SST / payment service fee** — not every China purchase has these, so it's a separate optional disclosure in the Costs form ("Add SST / payment service fee?"), not a permanent field. Fill in the goods cost, SST, and/or service fee only for the batches that had them, hit **Add to Amount**, and it sums into the Amount field. The breakdown is kept and shown as a small note under the amount in the Costs list, so you can still see how much was tax/fees vs. the goods themselves — but the total (Amount) is what counts toward your cost per unit if this cost is linked to a product with a quantity.
- **One payment, multiple products** — a single China order is often a mix of categories (tumblers + glitter + liquids in one payment). Tick **"This purchase covers multiple products"** in the Costs form and it swaps the single Related-product field for a repeatable list: pick a product (or **+ Add new product…**) plus quantity and unit cost per line. Amount is calculated automatically from all the lines. Any SST/service fee you add is split across the lines proportionally to their subtotal (a bigger line absorbs a bigger share) so each product's stock and cost price update with its true landed cost — no manual splitting by hand. Like single-product entries, this only happens when the cost entry is first created; editing it later just fixes the record without moving stock again.
- **Orders** — create orders with multiple line items (e.g. one line for the tumbler, one for the sticker code the customer picked). Picking an item is two or three dropdowns: Type → (Theme, for stickers) → the specific item. Stock is automatically deducted for every item when the order is saved, and restored if cancelled/deleted. Orders can be edited any time via the **Edit** button (like Inventory) — buyer info, shipping, and items all update together, with stock automatically re-adjusted for any item/quantity changes. Buyer info includes an optional **Telegram name** (shown under the buyer's name, since a lot of coordination happens off-TikTok) and **TikTok handle**, which gets its own column in the Orders table so it doesn't get crowded together with the buyer's name.
- **Payment tracking** — recorded *after* the order exists, not while creating it. Tick "Paid" directly in the Orders table any time. To log the reference number, payer's bank account name, and payment date, open the order and click **Edit details** — nothing saves until you press **Save** (so you can't accidentally overwrite something by misclicking). Unpaid orders show up in an "Awaiting payment" panel on the Dashboard. If an order's status is set to **Cancelled**, the Paid checkbox is replaced with a ⛔ so it can't be ticked — cancelled orders aren't expected to be paid.
- **Add-ons (decided after the order was placed)** — when a customer asks for something extra live, after you've already made/paid for the original tumbler, open the order and scroll to **Add-ons**. Click **+ Add add-on**, pick the item, quantity and price, and save — stock is deducted right away just like a normal order item, but it gets its **own separate Paid checkbox**, since it's a second payment. If the main order is paid but an add-on isn't, you'll see a red ⚠ next to the Paid checkbox in the Orders table, and the order counts as "awaiting payment" on the Dashboard (labeled "(add-on)" so you know it's not the whole order). Trying to mark the order **Shipped** or **Delivered** while anything is still unpaid — the order itself or an add-on — pops up a confirmation first, so you don't accidentally ship before you've actually been paid in full. Removing an add-on restores its stock.
- **Shipping** — **Ship to** is a roomy, multi-line text box for the customer's actual delivery address (street, unit, city) — big enough to paste a full address without it scrolling out of view, with its own separate **Postcode** field next to it. Region-specific logic (free vs. charged, weight tiers) lives in the separate **Shipping zone** field below (see the calculator right after). The form also records the shipping fee you charge the customer, the actual courier cost you paid, and a tracking number. Charged fee counts as revenue; actual cost counts against profit. The quick "Edit details" panel (for editing an order after it's created) has the same wide address box + Postcode field, so you don't need to reopen the full order form just to fix an address.
- **Shipping zone calculator** — pick a **Shipping zone** (西马 West Malaysia / 东马 East Malaysia / 新加坡 Singapore / Other) and, for 东马/新加坡, the **package weight**, and the form shows a suggested fee + cost with an **Apply** button to fill in "Shipping fee charged" and "Shipping cost you paid" for you — you can still edit either field afterward, this is just a starting point. The rules baked in: 西马 is always free for the customer (RM7 courier cost absorbed as your cost, no weight surcharge); 东马 is free once the order subtotal hits RM100, otherwise the customer pays the weight-based courier rate (RM13.70 at 1kg / RM20.60 at 2kg / RM37.90 at 3kg) with no markup; 新加坡 is never free — always the weight-based rate in SGD (S$22.80 / S$30.05 / S$36.20 at 1/2/3kg) converted to RM at an editable exchange rate (defaults to 3.4), also no markup. Above 3kg, or for "Other" zones, there's no rate on file — the app tells you so and leaves the fields for you to fill in by hand.
- **Calendar** — a month-grid view so you can see scheduled orders and your own availability at a glance. Every order with a make/ship date shows up as a chip on its day (click a chip to jump straight to that order). Click any day to open an edit panel — tick **Personal day** (unavailable for customer slots) and optionally add a short note like "family gathering" — nothing changes until you press **Save** (matches the same Edit/Save pattern as order payment details, so a stray click can't accidentally mark or unmark a day). If a personal day already has an order scheduled on it, the cell turns red as a conflict warning so you catch it before you commit to a customer. Once a day is marked personal, a **Clear** button appears next to Save/Cancel — clicking it asks you to confirm before wiping the day's personal-day flag and note, so undoing a mistaken entry is safe and deliberate rather than an accidental unmark. Navigate months with Prev/Next/Today — the calendar always opens on today's month when you load the page, but if you leave the tab open across a month boundary without reloading it won't jump forward on its own; hit **Today** to snap back.
- **Give a range, confirm later — without losing track** — for a "give customers a rough window, confirm the exact day closer to the time" workflow, every order has its own **Scheduling** section (expand the order — no need to click "Edit details" for this, it's always visible) with a clear 3-step flow:
  1. **Rough target date** — internal-only, never shown to the customer, just something to jog your memory about roughly when you're aiming for. You can also set this right when you create a new order (there's a "Rough target date" field in the New order form) — if you leave it blank while creating a new order, a confirmation pops up reminding you to set one before you save, so it doesn't quietly slip through unset. (Editing an existing order later doesn't nag you again.)
  2. **Notified customer** checkbox — tick once you've actually messaged them to ask for their preferred exact day. A red ⚠ warning appears here (and on the Dashboard) once the rough date is within 5 days and you haven't ticked this yet, so you don't forget to reach out. Changing the rough target date automatically un-ticks this, since you'd need to notify again.
  3. **Confirmed date** — the real, locked-in date once the customer replies. This is what shows up on the Calendar and groups the order in the Schedule tab.

  Both the Rough target date and Confirmed date fields have a **Clear** button next to them (whenever a date is set) so a mistaken click is easy to undo — just clear it and re-enter, no need to overwrite one wrong date with another guess. Clearing the rough date also un-ticks "Notified customer," same as changing it.

  In the Schedule tab, every unscheduled order also shows its **queue position** ("#3 in queue") so you can tell a customer "you're #3, expect around [your rough window]" without committing to a date. The Dashboard's **🔔 Confirm dates soon** panel lists every order whose rough target date is due (within 5 days or overdue) and still has no confirmed date, tagged "⚠ notify" or "✓ notified" so you can see at a glance who still needs a message — click a row to jump straight to that order. Note this is an in-app reminder, not a push notification: it only surfaces when you actually open the Dashboard, since a static page with no backend can't message you when the app isn't open.
- **Schedule** — a dedicated tab for planning livestream production days. Once an order is paid, open it and assign it a make/ship date (or set it directly from the Schedule tab). Orders group by date — e.g. "Tuesday, Aug 4" — so you know exactly whose bottles to make that day. Anything without a date sits in "Unscheduled" at the top as a reminder. Tick **Done** on an order once you've made/shipped it and it moves out of the active list into a collapsed "Completed" section (untick to bring it back).
- **Sample data** — click "Load sample data" in the header to see all of this populated (tumbler + sticker orders, one paid/scheduled, one still unpaid/unscheduled), then clear it out and enter your own.

### How to record an order with a tumbler + a sticker

In Inventory, add the tumbler once (Type = Tumbler) and each sticker code as its own product (Type = Stickers, Theme = "A - Stitch" / "B - Winnie the Pooh" / etc., SKU = the code like `B003`). Add a photo to each sticker if it helps you tell them apart. When creating an order, click **+ Add item** twice: first line — Type "Tumbler" → pick the tumbler; second line — Type "Stickers" → Theme "B - Winnie the Pooh" → pick `B003`. Saving deducts stock for both automatically. If the sticker is bundled into the tumbler's price, leave its unit price at 0 so revenue isn't double-counted.

Hard-to-measure materials (glitter, etc.) don't need per-order tracking — just log them as a batch entry in Costs whenever you restock.

### Payment and scheduling workflow

1. Create the order as normal (no payment info needed yet).
2. When the customer transfers payment, go to Orders and tick the **Paid** checkbox for that row. If you want to log the reference number / bank name / date too, expand the order and click **Edit details**, fill it in, then **Save**.
3. Go to the **Schedule** tab (or the same "Edit details" panel) and set a make/ship date. The order will appear grouped under that date so you know what to prepare for each livestream.

## How data is stored

The app now signs in against **Supabase** and syncs your data across devices — sign in on your phone and your computer with the same account and you'll see the same data on both, no manual export/import needed.

- **Sign in required.** Opening the app shows a sign in / sign up screen first. Your data is private to your account — Supabase's Row Level Security means no one else can read or write your row, even though the app's URL and its "anon" API key are publicly visible in the page source (that key is meant to be public; it can't do anything without a valid login).
- **Still works offline.** Everything is also kept in this browser's `localStorage` as before, so you can keep using the app with no signal — changes save locally immediately and quietly sync up to your account once you're back online (there's a small "Synced / Syncing… / Offline" indicator in the header).
- **How sync resolves conflicts:** whichever device you last **signed in** on pulls down the cloud copy and treats it as current. If you make changes offline on two devices before either reconnects, the one that reconnects/syncs second will overwrite the first's changes — for a one-person shop this is rarely an issue, just try not to add orders on two offline devices back-to-back before either gets signal again.
- Use the **Export** button any time for an extra local JSON backup, independent of the cloud sync.
- Product photos are compressed and stored inline as part of the data (so they sync too), resized to a max of 900px so they still look sharp when you click to enlarge them.

### One-time Supabase setup

This only needs to be done once, by whoever owns the Supabase project:

1. Create a free project at [supabase.com](https://supabase.com).
2. In the Supabase dashboard, go to **SQL Editor → New query**, paste in the contents of `schema.sql` (included alongside this file), and run it. This creates the `app_state` table with Row Level Security so each account only ever sees its own data.
3. Go to **Settings → API** and copy the **Project URL** and **anon public** key (never the `service_role` key — that one's secret and must never go in frontend code).
4. In `index.html`, find the `SUPABASE_URL` and `SUPABASE_ANON_KEY` constants (search for `SUPABASE SYNC`) and make sure they match your project's values.
5. Under **Authentication → Settings**, consider turning off "Confirm email" so you can sign up and use the app immediately without waiting on a confirmation email — fine for a single-person tool like this.
6. Open the app, use the **Sign up** tab once to create your account, then **Sign in** from any other device with the same email/password.

## Run it locally

Just open `index.html` in a browser — no install needed. (Or use any static server, e.g. `npx serve .`.)

1. On [app.netlify.com](https://app.netlify.com), click **Add new site → Import an existing project**, and connect the GitHub repo you just pushed.
2. Build settings are already set via `netlify.toml` — no build command, it just publishes the folder as-is.
3. Deploy. Netlify gives you a live URL immediately.

Any time you `git push`, Netlify automatically redeploys.

## Notes

- Currency is MYR (RM) by default — search for `currency: 'MYR'` in `index.html` to change it. Everything (cost, price, revenue, profit) is meant to be in this one currency; use the "Paid in a different currency?" helper in Inventory/Costs to convert foreign purchases before they're saved.
- Selling a sticker as a paid add-on: set that sticker's own **Selling price** in Inventory to the add-on amount you charge (e.g. RM8) — this is what auto-fills when you add it as an order line. When it's the sticker *included* with a tumbler, just edit that line's price down to 0 in the order form so you don't double-count revenue.
- To wipe everything and start fresh (e.g. after trying out sample/test data), click **Reset all data** in the header — it asks you to confirm twice since it's permanent, then clears products, costs, orders and calendar data both locally and in your synced account.
